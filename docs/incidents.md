# Журнал типовых инцидентов

| Инцидент | Наблюдаемый признак | Первичный источник диагностики |
|---|---|---|
| Неиспользуемая переменная | Красная проверка `pylint` в PR | Журнал шага Static analysis |
| Недостаточные права публикации | `build` успешен, `deploy` не получает OIDC-токен | Журнал `deploy-pages` и блок `permissions` |
| Битая ссылка | `mkdocs build --strict` завершается ошибкой | Журнал шага Build documentation |
| Старая версия после успешного деплоя | Зелёный workflow, прежнее содержимое в браузере | URL окружения, время публикации, кэш браузера |

## Правило разбора
В разборе указываются симптом, затронутый компонент, доказательство из журнала, причина, исправление и проверка восстановления. Ответ «перезапустил и заработало» без установления причины неполон.

## Разбор инцидента №3: Неудачный выпуск документации

*   **Симптом:** failed workflow Publish documentation после merge в ветку `main`. Джоба `deploy` не запускается (находится в статусе skipped).
*   **Затронутый компонент:** сборка MkDocs, задание `build`.
*   **Доказательство:** сообщение об ошибке в логе шага "Build documentation" о битой ссылке на файл `docs/recovery.md`; завершение шага с ненулевым кодом возврата (из-за флага `--strict`).
*   **Причина:** в тексте документации добавлена ссылка, указывающая на несуществующий файл. Благодаря флагу `--strict`, MkDocs превратил предупреждение о битой ссылке в критическую ошибку, прервавшую сборку.
*   **Исправление:** удаление битой ссылки (или создание отсутствующего файла `docs/recovery.md`) в новой ветке, отправка изменений через Pull Request.
*   **Проверка восстановления:** успешное прохождение шага "Build documentation", запуск и успешное завершение задания `deploy`, появление обновленной версии сайта по URL из окружения `github-pages`.
*   **Влияние:** новая версия не опубликована; так как задание `deploy` не было запущено, предыдущая версия сайта остаётся доступной для пользователей.
